# Phase 1 実機確認の結果

2026-09-15、macOS 27.0 (26A428)、Apple Silicon。

**未解決だった 3 点すべてに答えが出て、プリセット値とプレビューの設計が確定しました。**
2 回の完走はどちらも同一の数値を出し、いずれも終了後に元の「未設定」状態へ復元されています。

## 方法

`spikes/run_phase1.py` は、書き込み前に 2 キーの正確なバックアップを取り、
コーディネータが死んだ場合に復元する外部ウォッチドッグを起動し、
すべての変更をロックで直列化し、復旧開始後は以後の実験的書き込みを拒否します。
書き込んだのは current-user / current-host / 全アプリケーションドメインの
`NSStatusItemSpacing` と `NSStatusItemSelectionPadding` だけです。

`Sources/SpacingProbe` は調査時と同じ 3 項目——可変長テキスト、正方形シンボル、固定幅 32——を
作成し、AppKit の幾何情報を 3 回記録します。直近 2 サンプルが一致しない限り計測値として
採用しません。設定に触れる前に、コーディネータの 20 件のガードテストが走ります。

以下の数値は **AppKit が報告する points 単位の幅であり、アイコン間の実測ピクセル間隔ではありません**。
また自作フィクスチャの値であって、他のアプリケーションの値ではありません。

## 1. 各プリセット値の効果

ステータス項目のウィンドウ幅。テキスト項目の intrinsic 幅は 21pt です。

| 段階 | 可変長テキスト | 正方形シンボル | 固定幅 32 |
|---|---:|---:|---:|
| キー未設定（OS 既定） | 37 | 38 | 48 |
| 両キー 4 | 25 | 26 | 36 |
| **両キー 8** | **29** | **30** | **40** |
| 両キー 24 | 45 | 46 | 56 |
| 復元後（未設定） | 37 | 38 | 48 |

`幅 ≒ intrinsic + N` はすべての実測点で成立しました。8 は 2 点仮説の予測どおり
ちょうど 29 になり、`narrow` は内挿値ではなく実測値になりました。
各段階の幾何は互いに異なり、OS 既定は N ≒ 16 相当の振る舞いをします。

各段階のプローブは、見えるはずの値をそのまま読み返しており
（`{spacing: 4, padding: 4}` など）、復元段階はベースラインの幾何を正確に再現しました。

## 2. 同一プロセス と 子プロセス

1 つのプロセスが 3 項目を作り、未設定の状態から両キーに `4` を書き、
そのあとさらに 3 項目を作りました。

| 観察 | 結果 |
|---|---|
| 既に存在していた項目 | 変化なし（37 / 38 / 48） |
| **同一プロセス内で新規作成した項目** | **変化なし（37 / 38 / 48）** |
| **そのプロセス自身が起動した子プロセス** | **25 / 26 / 36 — 新規プロセスと完全一致** |

つまり値はステータス項目単位ではなく**プロセス単位で固定**されます。プロセスは起動時点で
有効だった間隔を保持し、項目をいつ作っても変わりません。設定を書いて短命な子プロセスを
起動すれば十分で、アプリ自身を再起動する必要はありません。

**製品への帰結。** プレビューは子プロセスで実装します。値を適用し、同じ実行ファイルを
プレビューモードで起動し、自分のステータス項目を見せて終了する。RFP に書いた
「アプリ自身を再起動する」フォールバックは不要になりました。

## 3. 書き込み後の読み返し

すべての書き込みで読み返しの検証が通りました。current-host スコープには書いた値がそのまま入り、
削除経路は current-host と any-host の両スコープで 2 キーを未設定に戻しました。
プローブは不一致を成功と見なさずエラーコードで報告しますが、2 回の実行とも不一致はありません。

## これで確認できていないこと

- 他のアプリのメニューバー項目、Apple 純正項目、複数ディスプレイ、
  項目があふれたときのレイアウトは未計測です。観察したのは自作フィクスチャだけです。
- これは AppKit の幾何値であって描画されたピクセル間隔ではなく、
  圧縮値でクリックしやすさが保たれるかの判断でもありません。
- macOS 更新後も同じ挙動が続く保証は何もありません。この設定は非公開のままです。
- 2 キーの個別効果は依然として不明です。製品と同様、常に同時に変更しました。

## 再現方法

```bash
swift build -c release
python3 spikes/test_phase1.py                       # コーディネータのガード 20 件
python3 spikes/run_phase1.py run /absolute/out.json
```

実行時に一時ディレクトリのパスが表示されます。何か変更が残った場合は
`python3 spikes/run_phase1.py restore /absolute/表示されたディレクトリ` で
バックアップした 2 キーを元に戻せます。間隔の実験を同時に 2 つ走らせないでください。
